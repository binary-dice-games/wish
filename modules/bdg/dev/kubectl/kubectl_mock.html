Kubectl frontend — UI mockup

A Kubernetes-dashboard–style GUI over the local kubectl CLI. Six independently dockable windows, docker/git-module style: list views for pods / deployments / services / nodes, plus Logs and Describe. All kubectl calls run client-side against the current kubeconfig context; the server form only renders.

Static stand-in. This page mirrors the widget tree in kubectl_mock.json (which renders live in the editor tool). It exists to review columns, toolbars, and the confirm-gating at full width in one view. Sample rows are illustrative, not real cluster output.

Server → client events

refresh_requested {}
pod_action_requested { name, namespace, action }
deployment_action_requested { name, namespace, action }
service_action_requested { name, namespace, action }
node_action_requested { name, action }
logs_requested { name, namespace, follow, lines }
describe_requested { kind, name, namespace }
closed {}

Client → server render methods: update_pods, update_deployments, update_services, update_nodes, update_logs, update_describe, command_result.

Refresh is manual: a Refresh button per window plus an automatic refresh after every mutating action — no background polling (the git module's jitter lesson, inherited via docker). The Logs “Follow” toggle is a 2 s client-side re-poll, not kubectl logs -f streaming. Lists are always fetched with -A; namespace is a client-side filter. Full rationale in modules/bdg/dev/kubectl/DESIGN.md.
