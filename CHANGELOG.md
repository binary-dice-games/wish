# Changelog

All notable user-facing changes to wish are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Resource package sync: `sync_resource_package(name, zip, dest_path, on_progress, on_done)` on `wish::client`, `wish::standalone` and `wish_app_host` uploads a zip and unpacks it into the sandbox in the background, only when the local zip changed since the server last unpacked package `name`. C ABI `wish_sync_resource_package()` / `wish_wait_resource_syncs()`; `sync_resource_package` / `SyncResourcePackage` / `syncResourcePackage` in the C++, Python, C#, Rust, Go and Java bindings.
- `file_service::unpack()` with an empty `dest` extracts into the sandbox root.
- Server overlay (see [docs/server-overlay.md](docs/server-overlay.md)): Shift+F1 (new `--overlay_hotkey` flag; also **Server → Overlay**) opens a Steam-like full-screen overlay over every app on `wish server`, with an overview of the server and the local machine, the connected clients, a settings editor for the server store and each user store, the live server log, links to the project and its documentation, and buttons to open the sandbox and log folders and to shut the server down. A notification at startup shows the key.
- Toast notifications: `wish::notification_center` (`renderer::notifications()`, `context::notifications`) lets server-side code post info/success/warning/error toasts, drawn in a corner of the server's screen.
- Apps post notifications too: `notify()` / `dismiss_notification()` / `has_notifications()` on `wish::client`, `wish::standalone` and `wish_app_host`; C ABI `wish_notify()` / `wish_notify_dismiss()` (`WISH_NOTIFY_*` kinds); `notify` / `Notify` / `showNotification` in the C++, Python, C#, Rust, Go and Java bindings. Each shows the sender's identity; at most 4 per session.
- Server overlay **Performance** page: two minutes of frame time, frames drawn, CPU, memory and clients, and Start/Stop recording of a Perfetto trace when the server runs with `--profiling_dir`.
- Every registered theme everywhere a theme is picked: the desktop tray's theme button opens a menu of all of them, `toggle_theme` cycles through all of them, and the server overlay gets a **Theme** picker (its own look, or any theme; saved as `wish.server.overlay.theme`). The Settings choices for `--theme` and the desktop theme list them too. `registered_themes()` / `find_theme_info()` (theme catalog, `style_service.hpp`), an optional `label` for `register_theme()`, the `__WishStyle.themes` RMI method and `client::list_themes()` / `standalone::list_themes()`.
- Server overlay **Screenshot** button: saves the clients' windows (without the overlay) as a PNG in `--screenshot_dir` (default `wish_screenshots`); works with the SDL3 and the web renderer. `renderer::request_screenshot()`.
- `wish desktop --with_server`: runs the wish server in the desktop's own process, connected through the in-memory transport, so a single command starts both (`wish` binary only; the `wish server` flags such as `--renderer` apply).
- `wish desktop`: an app's main window has Windows-style minimize, maximize/restore and close buttons at the top right of its title bar (double-click the title to maximize), and a border with a shadow that sets it apart from overlapping windows.
- "Reset layout" puts an app's panels back in their default arrangement: from the app window's title-bar menu (right-click the title; it also has Maximize/Restore, Minimize and Close) or its taskbar button on `wish desktop`, or by changing the new `DockSpaceViewport.layout_reset_request` field.
- `DockSpaceViewport.closable`: a close button on the app frame that emits `closed` (also offered as "Close window" on the desktop taskbar); `dock::viewport()` frames are closable.
- Keyboard-only control of every wish UI, Windows-style (see [docs/ui-elements.md](docs/ui-elements.md#keyboard-navigation-access-keys-and-shortcuts)): Tab/Shift+Tab between controls, arrow keys in menus, Space/Enter to press, Esc to close.
  - Access keys: a `&` before a letter in a `Button`, `MenuButton`, `Checkbox`, `RadioButton`, `Menu`, `MenuItem`, `TabItem` or input label (`"&File"`) underlines it and makes Alt+letter (the bare letter inside an open menu) activate the control; `&&` is a literal `&`.
  - Functional shortcuts: `MenuItem.shortcut` (e.g. `"Ctrl+S"`, `"F5"`) now fires `clicked` while its menu is closed; new `shortcut` field on `Button` (shown in its tooltip as "Save (Ctrl+S)") and `MenuButton`.
  - `Shortcut` element: an invisible key binding (e.g. `F1`) that emits `pressed`.
  - The bundled tools use it: Windows-style access keys on their buttons, checkboxes, tabs and menus in English, Spanish and French; `F5` refreshes (docker, kubectl, helm, pip, pkg, git, zip, du, details panels) or runs the query (sq) or copies to the other panel (mc); `Ctrl+O`/`Ctrl+N`/`Ctrl+S`/`Ctrl+H` in nano; `Ctrl+Enter` sends (curl) and commits (git); pix zoom keys; bc follows Windows Calculator's keys (digits, operators, `Enter`, `Esc`, memory, `Alt+1`-`Alt+3` modes); message boxes and dialogs take `Enter` for the default button and `Esc` to cancel.
  - Shortcuts take comma-separated alternatives (`"5, Num5"`) and keypad keys (`Num0`-`Num9`, `NumPlus`, ...); `Shortcut.scope` / `Button.shortcut_scope` `"app"` makes one work from any window of the same app; Ctrl/Alt/function-key shortcuts also work while typing in a text field; an `Enter` default button yields to the keyboard-focused control.
- `bdg/desktop/find` module, **Find**: instant file search modelled on FSearch -- indexes local folders into an in-memory database and searches it as you type (wildcards, `OR`/`!`, `ext:`/`size:`/`dm:`/`folder:` functions, Match Case / Search in Path / Regular Expression modes, a type filter), with a sortable results table, multi-selection, open / open folder / copy path actions and a status bar (`wish client --run=find -- [FOLDER...]`).
- `top` module: **Network** and **Disk I/O** panels (throughput graphs with auto-scaled units, plus totals) and a **Ports** panel listing listening TCP/UDP sockets with their owning process. `Top.update_snapshot` accepts the matching optional `net_*`, `disk_*` and `ports` fields.
- Settings metadata (see [docs/settings.md](docs/settings.md)): apps describe the settings they keep in the user store (category, section, label, description, type -- bool, int, float, string, enum, color, path -- default, range, options, icon, order, restart note) and sidebar categories, so settings tools can edit them.
  - C++: `describe_setting()` / `describe_settings_category()` on `wish::client`, `wish::standalone` and `wish_app_host`; `wish::settings::describe()` / `describe_category()` / `collect()` / `write_setting()` for server code (`src/context/settings_store.hpp`).
  - C ABI `wish_settings_describe()` / `wish_settings_describe_category()` (JSON metadata), and the matching methods in the C++, Python, C#, Rust, Go and Java bindings.
- `wish_settings_read()` (C ABI) and `read_setting()` in the C++, Python, C#, Rust, Go and Java bindings: a setting's current value -- the stored one when valid, else its default (also for anonymous sessions).
- Module settings in Settings: bc, top, tail, nano, mc, zip, docker, kubectl, curl, git, sq, pip and helm list their settings under their own category, for every identity. Tools start with them and remember their toggles (bc's mode and View options, tail's Follow and Lines, nano's search options, the Logs window's Follow and Lines, curl's Follow redirects, sq's row limit, pip and helm install options).
  - New options: mc can hide dot files and keep folders on top; zip's compression level; top's refresh interval and graph history; tail's check interval; docker/kubectl stats interval; curl's request timeout and history size; git's commits in history.
  - `settings::register_setting()` / `register_category()` (settings server code registers for every user store), `settings::value_of()` / `bool_of()` / `int_of()` / `float_of()` / `text_of()`, and `wish_app_host::read_setting()` / `read_*_setting()` / `write_setting()`.
- `bdg/desktop/conf` module, **Settings**: a macOS System Settings-like editor built from that metadata -- a sidebar of categories with colored badges and search, a panel of grouped settings with an editor per type, reset to default, live refresh. Pinned in `wish desktop`'s default Start menu.
- `wish server --settings_admins=a,b` / `server::set_settings_admins()`: identities allowed to change server-store settings (e.g. the saved default theme) from the Settings tool; `wish standalone` is always admin. `context::identity` and `context::settings_admin`.
- `wish server` / `wish standalone` describe their common saveable flags (theme, text size, language, renderer, window, ports) and `wish desktop` its theme, so they show in Settings.
- UI styling for macOS-like layouts: `VerticalLayout`/`HorizontalLayout` `card` (+ `padding`, `rounding`), `Image` `badge`, `Checkbox` `style: "switch"`, `Selectable` `rounding` (rounded highlight, children laid out as a row).
- Python example `bindings/python/examples/desktop/settings_demo.py`.
- `wish desktop` is now a Windows/macOS-like desktop (see [docs/cli.md](docs/cli.md#wish-desktop)): wallpaper (built-in gradient, a color, or an image), desktop icons, and a bottom taskbar with a Start menu (searchable, with a power menu), pinned apps, a button per open app/window (minimize/restore/close), connected-app count, light/dark theme toggle, clock with a calendar and a show-desktop strip; Ctrl+Tab / Ctrl+\` window switcher.
  - The Start menu, initial pins and desktop icons come from a per-user config file, `~/.wish/desktop/desktop.yaml` (YAML or JSON; new `--config` flag), written with a default configuration if missing and reloaded live when edited (see [docs/desktop-config.md](docs/desktop-config.md)). Entries are folders, separators, `apps:` (the built-in apps), `run` commands (built-in modules or any client-ABI app, with `env`/`cwd`) and desktop `action`s, each with a label, icon and tooltip; errors are shown in the Start menu.
  - The config file also sets the wallpaper image (reloaded when the image changes) and how it fits the screen (`cover`, `contain`, `stretch`, `center`, `tile`), a background color, the theme, whether desktop icons are shown, and the clock's time and date formats.
  - Desktop actions (`quit`, `shutdown_server`, `set_theme`, `toggle_theme`, `reload_config`, `launch`, `items`), callable from menu entries and by connected apps through a `__WishDesktop` object.
  - Apps started from the desktop run as `wish client --run=<app>` subprocesses connected back to it, logging to `wish_logs/desktop/`, and are closed when the desktop quits.
  - Pinned apps, desktop icons and the theme persist in the upstream user store (entry `wish.desktop`); new `--upstream_username` flag (default: the OS user name).
- `DesktopShell`, `DesktopMenu` and `DesktopApp` UI classes, the server-side desktop chrome behind `wish desktop`.
- `yaml_to_json()` (`src/ui/yaml_json.hpp`): parse YAML or JSON text into ordered JSON; YAML syntax errors now report their line and column.
- `app_info::icon`: an optional icon per embedded app; every `bdg` app has one.
- Built-in icons `apps`, `desktop`, `push_pin`, `power`, `calculate`, `monitoring`, `pie_chart`, `log`, `helm` and `container`.
- `wish client --run` sends the app's qualified name in its connect params (`app`).
- Client-ABI apps on `wish desktop`: a client that sends `app` (plus optional `app_label` / `app_icon`) in its connect params shows on the taskbar with its own name and icon, like a built-in tool; `DesktopApp.listed` marks such taskbar-only entries.
- Python `Client.from_env()`: connect using the `WISH_TRANSPORT` / `WISH_HOST` / `WISH_PORT` / `WISH_NAME` environment variables.
- Python example apps for the desktop in `bindings/python/examples/desktop/` (to-do list, stopwatch, live chart).
- `wish desktop` listens on a fixed, system-wide local endpoint besides its downstream transport: the named pipe `\\.\pipe\wish-desktop` on Windows, the abstract socket `@wish-desktop` on Linux (`WISH_DESKTOP_ENDPOINT` overrides it). See [docs/cli.md](docs/cli.md#services-a-ui-whenever-the-desktop-runs).
- `wish client --transport=desktop` (and `WISH_TRANSPORT=desktop`): connect to the local desktop with no other flag.
- Desktop services: a long-running process gets a UI on the desktop whenever one runs, and again after the desktop is restarted. C ABI `wish_client_desktop_create()`, `wish_client_run_on_desktop()` and `wish_client_desktop_stop()`, wrapped in the C++, Python, C#, Rust and Go bindings (`desktop()` / `run_on_desktop()` / `stop_desktop()`, Python `Client.from_env()` with `WISH_TRANSPORT=desktop`).
- Python example `bindings/python/examples/desktop/service.py`.

- `wish server` / `wish standalone` `--save_defaults` and `--clear_defaults`: save the flags given on the command line (renderer, font size, language, theme, port, ...) to the server store as the defaults of later runs. Each flag now resolves as command line > `WISH_<FLAG>` env var > saved default > built-in default (see [docs/cli.md](docs/cli.md#saved-flag-defaults)).
- Internationalization (see [docs/i18n.md](docs/i18n.md)): template string values `"$$KEY"` are replaced from `<lang>.lang` translation files, falling back to English, then to the bare key.
  - Client side: `client::set_translations()` / `translate()` (applied by `register_template_from_json`/`_yaml`), `wish_set_translations()` / `wish_translate()` (applied by `wish_register_template`), and the same in the C++ header, Python, C#, Rust, Go and Android bindings.
  - Server side: session language via `--lang` (client, server, standalone), `client::set_language()`, `wish_set_language()`, `server::set_default_language()` and `wish_app_host::language()`. Tools load `res/<org>/<collection>/<name>/i18n/<lang>.lang` (`context::translations_for()`, `form::tr()` / `trf()`).
  - English, Spanish and French translations for the built-in forms (MessageBox, FileDialog, ProgressBox, PropertiesDialog), the shared tool panels and every `bdg` module (desktop and dev).
  - `format_text()` / `make_message()`: `{0}` placeholders, and messages that client code sends for the server to translate. Shared `COMMON_*` keys apply to every tool.
- Per-tool private directories in the session sandbox (`private/apps/<org>.<collection>.<name>/`) and session-owned temp dirs inside them, removed at session end: `file_service::app_private_dir()` / `create_temp_dir()`, `client::create_temp_dir()`, `standalone::create_temp_dir()` and `wish_app_host::create_temp_dir()` / `create_app_temp_dir()` / `running_app()`.

- `icon` field on `Button`, `MenuButton` and `MenuItem` (plus `Button.icon_color`): an image drawn left of the label, tinted to the text color; an empty label gives a square icon-only button.
- Icons on the toolbar buttons and row/context menus of every `bdg` module (docker, kubectl, helm, pip, pkg, curl, sq, git, nymph, bc, du, mc, nano, pix, tail, top, zip); table row action menus are now an icon-only "more" button.
- Built-in icons `send`, `merge`, `commit`, `fit_screen` and `table`.
- 25 more built-in icons, e.g. `visibility_off`, `lock_open`, `fullscreen`, `dark_mode` / `light_mode`, `login` / `logout`, `key`, `sync`, `chart`, `calendar` and `tag` (full list in `resources/README.md`).
- The bdg tools use some of them: `sync` for git Fetch, helm "Update all", pkg "Update index" and row "Update" actions; icons on git's Local / Remote-tracking / Tags / Stashes sections; `key` / `link` on sq primary- and foreign-key columns; `bookmark` on curl's Save; `tag` for pip "Versions"; `lock_open` for kubectl Uncordon. Row actions such as Load, Duplicate, Show / Hide, Share or Print now get icons automatically too.

- Persistent stores of bison objects kept across sessions and server restarts (see [docs/persistent-store.md](docs/persistent-store.md)):
  - A **user store** per authenticated identity (`~/.wish/users/<identity>.bison`), readable and writable by that identity's clients via `has_user_store()` / `user_store_get` / `user_store_set` / `user_store_erase` / `user_store_keys`.
  - A **server store** (`~/.wish/server_store.bison`) for server-side code only (`server::server_store()`, `context::server_store`).
  - The user store API is in `wish::client`, `wish_app_host`, `wish::standalone`, the C ABI (`wish_user_store_*`, new `WISH_ERR_UNAVAILABLE`) and the C++ header, Python, C#, Rust, Go and Android bindings.
- `wish server` / `wish standalone` `--store_dir`, `server::set_store_dir()` / `standalone::set_store_dir()`, `standalone::set_user_identity()`, and a `store_dir` param for `wish_server_start()`.
- `du` module (`WISH_MODULE_BDG_DESKTOP_DU`): a disk usage analyzer, run with `wish client --run=du [-- <folder>]`. Scans a folder on the client's machine and shows what takes the space as a size-sorted table (share of the folder, size, item count) and a treemap colored by file type; double-click a folder or its rectangle to open it.
- `DockSplit.size` (`dock::split_px()`): give the first pane of a dock split a size in pixels instead of a ratio, e.g. a fixed-width side panel.
- `Treemap` element: a squarified treemap of weighted nodes given as flat `parents` / `sizes` / `colors` arrays and newline-separated `labels`, with hover tooltips, a `selected` outline and `clicked` / `activated` events.
- `mc`: a folder tree panel next to each file panel (**Local Folders**, **Sandbox Folders**). Each node shows a folder icon. Clicking a folder navigates that side's file panel; navigating the file panel (path bar, opening a folder) expands the tree to that folder and selects it. Trees are filled one level at a time, as nodes are expanded. Custom `Mc` clients should handle the new `on_local_tree_expand` event and call `update_local_tree`.
- `TreeNode`: `selected` (highlight), `icon` (image before the label), `open_on_arrow` (only the arrow toggles) and a `clicked` event; changing `open` after creation now expands/collapses the node, and a user toggle is written back to the field.
- `nymph`: a `view` command (`wish standalone --run=nymph -- view chart.png`) shows a chart's interactive preview and its data table read-only, with no source editor and no Save.
- Plot series (`PlotLine`, `PlotBars`, ... and the `Plot3D*` series) gain styling fields: `color` and `fill_color` (`"#RRGGBB"` / `"#RRGGBBAA"`), `line_weight`, `fill_alpha`, `marker` (`Circle`, `Square`, `Diamond`, ...) and `marker_size`. `Plot` and `Plot3D` gain `colormap` (`Deep`, `Dark`, `Viridis`, `Jet`, ...). All default to automatic.
- `nymph` module (`WISH_MODULE_BDG_DEV_NYMPH`, off by default): charts from text. A source file (description, format YAML built from wish's `Plot` / `Plot3D` elements, data CSV) is rendered to a PNG that carries the source as metadata, so the image can be given back to the tool. `wish standalone --renderer none --run=nymph -- render chart.nymph -o chart.png` needs no window or display and exits non-zero with a `file:line:column: message` error; `edit` opens the source with a live plot preview and a data table; `extract` prints the source embedded in a PNG.
- `wish standalone --renderer none`: runs an app with no window and no web server, for apps used as command line tools. The log then goes to the system temp directory instead of `./wish_logs`.
- `wish_app_host::set_exit_code()`: an embedded app can set the exit code `wish client` / `wish standalone` return.
- `find_theme()` (`src/imgui/imgui_renderer.hpp`): look up a registered theme's style function by name.

- `ProgressBox`: `update` accepts an optional `fraction` (0..1) and `detail` text for a determinate bar, e.g. bytes transferred.
- `Window.dock_target`: a window created at runtime docks into a named `DockSpaceViewport`'s central node (left empty by an empty `DockArea`) instead of the outer dockspace.
- `Window.focus_request` (change it to bring the window or its dock tab to the front) and a `focused` event when a window gains focus.
- `TextEditor` `goto_line` / `goto_column` / `goto_length` / `goto_request`: select a range, scroll it into view and focus the editor.
- `DockArea` may list no windows, reserving an empty node.
- `pkg` module (`WISH_MODULE_BDG_DEV_PKG`, off by default): one GUI over the system package managers apt, dnf, pacman and brew, run with `wish client --run=pkg [-- <manager> [sudo|pkexec|none]]`. Lists installed packages (filter, update check), searches the index, installs / upgrades / reinstalls / removes, and upgrades everything; prints a descriptive console error when the chosen manager is not installed.
- `Table` gains `resize_pushes` (dragging a column border pushes the following columns instead of taking width from a neighbour) and `cell_tooltips` (hovering a cell shows its Label's full text).
- `ProgressBox` built-in form: a modal progress dialog (indeterminate bar, live output log, Cancel) for long-running client-side operations, driven with `update` / `finish`.
- `pip` module (`WISH_MODULE_BDG_DEV_PIP`, off by default): a GUI frontend for the local `pip` CLI, run with `wish client --run=pip [-- <python-or-venv>]`. Lists installed packages (name filter, outdated check), installs requirements or a requirements file, upgrades / reinstalls / uninstalls per row, lists the versions the package index offers, and shows `pip show` / `freeze` / `check` output, with a Console tracing every `pip` command. Long commands run in the background behind a modal dialog with a progress bar, pip's live output and a Cancel button.
- `helm` module (`WISH_MODULE_BDG_DEV_HELM`, off by default): a GUI frontend for the local `helm` CLI, run with `wish client --run=helm`. Ships six dockable windows — Releases, Repositories, Charts, History, Details, and a Console that traces every `helm` command — with per-row status/values/manifest/notes/history, rollback, uninstall, and repository add/update/remove, plus an Install / Upgrade dialog (chart, version, release, namespace, custom YAML values).
- `TextEditor` gains an `auto_scroll` field (scroll to the last line whenever the file is reloaded) and a `"log"` highlighting language for plain-text log output.
- `sq` Results and Chart windows have an "Open folder" button that opens the session sandbox folder (where Export CSV / Save PNG write) in the server machine's file manager.
- `wish server --sandbox_root PATH` keeps session sandboxes across connections (one `PATH/<username>` directory per client, `default` if none), and `wish client --username NAME` selects which one. `wish standalone` accepts the same `--sandbox_root`/`--username` pair. Trusts the client-supplied name; local/single-user use only.
- `sq` module (`WISH_MODULE_BDG_DEV_SQ`, off by default): a DBeaver-style, query-only database GUI frontend for the local [`sq`](https://github.com/neilotoole/sq) CLI, run with `wish client --run=sq`. Ships seven dockable windows — SQL Editor (active-database picker, row limit, Run, Export CSV), Results (dynamic-column grid), Connections (list/ping/remove sq sources and add a new one, password passed on stdin), Navigator (tree of tables/views/columns with View data and Structure actions), Structure (columns, keys, foreign-key references) and a Console tracing every `sq` command, plus a Chart window that plots the last result (line, scatter, stairs, stems, area, bars, horizontal bars, histogram or pie) from user-chosen X and Y columns and can save the chart as a PNG image. Only read-only SQL is accepted; Export CSV re-runs the last query in full. Export CSV and Save PNG write to a path inside the server-side session folder. If `sq` is not installed the tool shows a message pointing to its GitHub repository.
- `curl` module (`WISH_MODULE_BDG_DEV_CURL`, off by default): a Postman-style REST API client GUI frontend for the local `curl` CLI, run with `wish client --run=curl`. Ships six dockable windows — Request (method/URL/environment/follow-redirects toolbar, an inline "Save as" row, and Params/Headers/Body/Auth tabs), Response (colour-coded status line, headers table, a JSON-aware pretty-printed/syntax-highlighted body viewer), History (every sent request, reloadable), Collections (named/saved requests grouped by collection, load/duplicate/delete), Environments (named `{{name}}` variable sets substituted at send time), and a Console that traces every `curl` invocation the module runs (command, exit code, output; green/red). Params/Headers/Form-body/Environment-variable rows are editable key-value tables (add/remove one row at a time, live-typed values). Collections/Environments/History persist in the session's user store (connect with `wish client --username NAME`; an anonymous session keeps them in memory only). All `curl` invocation is client-side, no shell, real argv.
- `DockLayout` / `DockSplit` / `DockArea` elements: a UI (a server-side `wish::form` via `form::set_default_dock_layout()`, or a client-registered template descriptor) can declare the initial docking arrangement of its windows. The renderer realizes the split tree via ImGui's DockBuilder on first run, after the element's `version` increases, or when a sibling tool sharing the dockspace has rebuilt it — otherwise it leaves the arrangement to `imgui.ini` like any user drag. Build the tree from C++ with the `bdg::wish::dock::` helpers in `src/ui/dock_layout_spec.hpp`. See [docs/dock-layout.md](docs/dock-layout.md).
- `DockSpaceViewport` gains a `title` field: the user-facing name shown on the tab/title bar when `embedded`, distinct from `id` (which stays purely internal -- the DockSpace/DockBuilder identity and any nested `DockLayout.target` are still derived from `id` alone). `dock::viewport(id, title, layout(...))` now takes the display name as its second argument; `docker`/`kubectl`/`git` now show "Docker"/"Kubectl"/"Git" instead of their internal `*_dock` ids.
- `DockSpaceViewport` gains an `embedded` field: when true, it renders as an ordinary dockable window (one tile among its siblings, docking into whatever dockspace is already ambient on first use) carrying its own nested `ImGui::DockSpace()`, instead of the fullscreen, non-dockable host chrome. Combined with a `DockLayout` whose `target` names that same id, an app's whole window set can be wrapped into one isolated, nested dock tree that a sibling app sharing the same outer host dockspace can never rearrange or evict — build one with `bdg::wish::dock::viewport(id, layout(...))`. `docker`, `kubectl`, and `git` all now opt into this. See [docs/dock-layout.md](docs/dock-layout.md).
- `Plot` gains `legend_location` (`ImPlotLocation`) and `legend_flags` (`ImPlotLegendFlags`) fields for placing the legend — e.g. `legend_location: "South"` + `legend_flags: "Outside"` renders it below the plot instead of over the trace.
- `docker` module: new **Stats** window — live `docker stats` CPU % and memory % history graphs (one `PlotLine` per running container, capped at the 15 busiest, plus a "Total" line) and a current-values table (Name / CPU % / Mem % / Mem Usage). Sampled by a background poll thread every ~3 s; these polls are not shown in the Console window.
- `kubectl` module: new **Top** window — live `kubectl top` graphs: pod CPU (millicores) and pod memory (MiB) with a per-pod line (top 15) plus "Total", node CPU % and node memory % with a per-node line plus "Cluster avg", and current-values tables for pods and nodes. Sampled by a background poll thread every ~10 s; these polls are not shown in the Console window. Shows a status message when `kubectl top` is unavailable (e.g. metrics-server not installed).

- `kubectl` module (`WISH_MODULE_BDG_DEV_KUBECTL`, off by default): a Kubernetes-dashboard-style GUI frontend for the local `kubectl` CLI, run with `wish client --run=kubectl`. Ships seven dockable windows — Pods, Deployments, Services, Nodes, Logs, Describe, and a Console that traces every `kubectl` command the module runs (command, exit code, output; green/red) — each list window a table with a per-row `...` action menu (pod delete; deployment rollout-restart/delete; service delete; node cordon/uncordon/drain; logs; describe), plus name/namespace and pod-phase filters, and a `MessageBox` confirm on delete/drain. All `kubectl` invocation is client-side against the current kubeconfig context; refresh is manual (Refresh button + after every action), no background polling.
- `docker` module (`WISH_MODULE_BDG_DEV_DOCKER`, off by default): a Docker Desktop-style GUI frontend for the local `docker` CLI, run with `wish client --run=docker`. Ships seven dockable windows — Containers, Images, Volumes, Networks, Logs, Inspect, and a Console that traces every `docker` command the module runs (command, exit code, output; green/red) — each list window a table with a state-aware per-row `...` action menu (start/stop/restart/pause/unpause/kill/remove, image run/remove, volume/network remove, inspect), plus name/image and running/stopped container filters, inline pull-image and create-volume fields, and a `MessageBox` confirm on stop/kill/remove/prune. All `docker` invocation is client-side; refresh is manual (Refresh button + after every action), no background polling.
- `wish server` and `wish standalone` gain a `--allow_absolute_paths` flag, wiring the CLI up to the existing `wish::server`/`wish::standalone::set_allow_absolute_paths()` library setters. Required for any widget that references files by absolute path to show their contents.
- `wish_server_set_log_level()` (C ABI) and `set_log_level()` / `SetLogLevel()` (C++, Python, C# bindings): set the server log verbosity by name.
- Rust (`bindings/rust/`) and Go (`bindings/go/`) client language bindings for the wish client C ABI.
- Rust (`bindings/rust/wish-server/`) and Go (`bindings/go/wishserver/`) server language bindings: host and render a real wish session over `wish_server_c.h` (`Server`, `Params`).
- `examples/ui/json/` and `examples/ui/yaml/` — standalone editor example UIs, one file per tab of the `demo` app, in both formats.
- `tooltip` field on every UI element: when non-empty, its text is shown via `ImGui::SetTooltip()` while the element is hovered.
- `VerticalLayout` (and `TabItem`) gain a `scroll` boolean field: when true, the layout's children render inside a vertically-scrolling child region sized to the space the layout was given, so overflowing content scrolls instead of clipping the enclosing window.
- `TextEditor` gains `breakpoint_lines` (int array, 1-based) and `current_line` (int, 1-based, 0 = none) fields, rendering a breakpoint dot / current-line arrow in the gutter, and a `"line_context_menu"` event (`{line, has_breakpoint}`) emitted on a gutter right-click.

### Fixed

- Opening or closing an instance of a tool no longer detaches the panels of another open instance of the same tool: an instance's window names no longer change while it is open (they depended on the order of random object ids). Two clients running the same tool on one server no longer share windows either.
- `wish desktop`: starting several instances of one tool no longer asserts on a shared dockspace; each instance gets its own.
- Web renderer: the punctuation keys (`-` `=` `,` `.` `/` `;` `\`) and the numeric keypad now reach the server as keys, not only as typed characters, so shortcuts using them work in the browser.
- Clients over the `pipe` transport notice when the server goes away (they hung in `wait()` before) and can connect again; a server on a pipe no longer risks a crash when stopped (bison update).
- The windows of a client that was killed or lost its connection now disappear: the server drops the session when the connection closes, not only on an explicit disconnect (bison update).
- `nano` no longer writes its working copies at the sandbox root, where they collided with other tools' files and earlier runs in a persistent sandbox; they go in a temp dir private to nano and the session.
- The Details windows of the `bdg` tools (docker, kubectl, helm, pip, pkg) no longer overwrite each other's files when two sessions share a persistent sandbox.
- `git`, `nano`, `zip` and `du` toolbar buttons size to their label and icon instead of a fixed width, so their text is no longer cropped.
- `git`: clearing the Log window, or a long session pushing old rows out of it, no longer leaks each row's right-click menu objects.
- `mc`: the file tables' "Modified" column was too narrow for the full date and time, which looked like the scrollbar covering it; a listing now also opens scrolled to the top instead of the bottom.
- JSON/YAML UI descriptors now accept arrays of non-integer numbers (e.g. `"xs": [0.5, 1.5]`), and integer arrays are widened for `float[]` fields; previously plot data given in a template was silently dropped.
- A widget that grows after its first render (e.g. a `Label` whose text starts empty) inside a `HorizontalLayout` row is no longer clipped forever; the row now grows to fit it.
- A second confirmation dialog in the same session never appeared: a form that replaced a finished child dialog (`MessageBox`, ...) with a new one erased the new dialog along with the old. Affected every module that asks for confirmation more than once (`docker`, `kubectl`, `helm`, `git`, `curl`, `sq`, `pip`, `top`, `zip`).
- `docker`, `kubectl`, `helm`, `curl`, `sq`, `git`, and `pip` clients could crash on the command following one whose program failed to start.
- Buttons in the `curl`, `sq`, `docker` and `kubectl` modules size to their label instead of using a fixed width, so labels are no longer cropped.
- Buttons in the `pix` module size to their label instead of using a fixed width, so labels are no longer cropped.

- A scrolling `VerticalLayout` (`"scroll": true`) no longer draws its children under the vertical scrollbar, which cut off the right edge of the `kubectl` Top window's graphs and tables.
- wish server: fixed an intermittent crash when a client disconnected while the server was delivering it a widget event.
- `wish::server::start()` now stops its render loop again when listening fails (e.g. port already in use) before throwing, instead of leaving it running until the server is destroyed.
- `DockLayout`: manually rearranging windows was effectively impossible once a `DockLayout` was in use (e.g. in `docker`/`kubectl`) — dragging a window by its title bar or tab could snap the whole arrangement back to the default mid-drag or crash right after dropping, floating a single window out standalone reset the *entire* arrangement, and running one tool after another that shares the same host dockspace (e.g. `docker`, then `git`, then `docker` again) could reset the first tool's arrangement back to its hard-coded default on its next run. All of these came from the same root cause: the reapply check tried to infer "did a sibling app rebuild the shared dockspace" from transient or displaced window docking state, and reacted to that by rebuilding the coded default — discarding whatever the user had arranged. It now applies a layout at most once per `version`, full stop; once applied, nothing (a drag, a float-out, a sibling app rebuilding the shared dockspace) ever triggers another rebuild, matching how any other manually-arranged window is left to `imgui.ini` from then on.
- `CollapsingHeader` could not be collapsed/expanded by clicking unless the app wrote the new state back onto its `open` field in the `toggled` handler. The renderer now writes `open` back on toggle itself (matching `Checkbox`/`Slider`), so clicks work without app-side wiring.
- `DockLayout`: an app switching its layout to target a new, named dockspace (e.g. opting into `DockSpaceViewport.embedded`/`dock::viewport(...)`) while keeping the same windows and `version` left every one of its windows undocked on launch. The persisted "already applied" record was keyed only by the window-path list, not the target dockspace, so the unchanged version looked like a no-op re-run; its one fallback (reapply if the target node doesn't exist) never caught it either, because `ImGui::DockSpace()` auto-creates an empty node at a new id before the check runs. The target dockspace is now folded into that persisted identity, so a changed target is treated as a layout that has never been applied.
- `DockLayout`: a session's windows could still all end up crammed into one shared tabbed node instead of the intended split, even on a completely fresh run with no `imgui.ini` (e.g. `docker` standalone). `session::top_level_objects` iterates in arbitrary, unordered-map order, so a session's own windows could render (and resolve their first-ever dock placement) before that session's `DockLayout`/`DockSpaceViewport` got a chance to run `DockBuilderDockWindow()` in the same frame; ImGui then pruned the freshly-built, still-unhosted split nodes at end of frame, permanently collapsing the layout. Both the standalone and server render loops now always render a session's `DockLayout`/`DockSpaceViewport` top-levels before its other top-levels each frame, regardless of iteration order. See [docs/dock-layout.md](docs/dock-layout.md).

### Changed

- `wish server`: closing its window (close button, Alt+F4), **Server → Quit** and the `wish desktop` "Shut down server" action now ask for confirmation, with the same dialog as the overlay's **Shut down server** button (Ctrl+C still stops it right away). The desktop's "Shut down server" works again after a cancel; `DesktopShell.shutdown` is reset to `false` once seen.
- `wish desktop`: the tray's theme button opens a menu of every theme instead of switching between light and dark, and the `toggle_theme` action cycles through all of them.

- The bundled tools' panels no longer have a close button that closed the whole tool; the app window's close button (or the taskbar's "Close window") closes it. Dialogs, nano's file windows and its Search panel keep theirs.
- Only one `wish desktop` can run at a time: a second one prints `wish desktop is already running` and exits with 1.
- `wish desktop` exits when the wish server it draws on stops, releasing its endpoint (it used to keep running with nothing to show).

- `wish standalone` (and `wish-standalone`) now also reads `WISH_<FLAG>` environment variables as flag defaults, like the other modes.

- `Window`: changing `width` / `height` after creation now resizes the window, and a `NoResize` window always takes its `width` / `height` instead of a size remembered in `imgui.ini`.
- `bc` is now a full calculator with switchable **Standard**, **Scientific** and **Programmer** layouts (mode tabs or the View menu): operator precedence and parentheses, trigonometric (DEG/RAD/GRAD, inverse, hyperbolic), power/root/log functions, n!, mod, Exp entry and F-E notation; HEX/DEC/OCT/BIN with BYTE to QWORD word sizes, bitwise and shift/rotate operators; memory keys, a clickable history panel, digit grouping and Copy.
- `wish server` and `wish_server_start()` always trust a client's `--username` / `"username"` connect field as its identity, so it gets a user store; clients without one stay anonymous.
- `mc`: the default layout is now a 2x2 grid -- folder trees on top, file panels below, Local on the left and Sandbox on the right.
- The bdg tool frontends (`kubectl`, `docker`, `helm`, `pip`, `pkg`, `curl`, `sq`, `git` and the desktop tools) now share one set of server-side panels (`modules/bdg/common/server/`): the Console window, list windows with `...` row menus, read-only text viewers, live stats graphs and confirm dialogs look and behave the same in every tool.

Graphs and the process table fill their panels; closing any panel closes the tool.

The form's `progress` / `progress_label` fields and its built-in progress bar are removed.

The client opens every file given on the command line.

- Tables in the `docker`, `kubectl`, `helm`, `pip`, `curl`, `sq`, and `git` modules: resizing a column now pushes the columns to its right (the table scrolls horizontally) instead of shrinking the next one, and hovering a cell shows its full value in a tooltip.
- `docker`, `kubectl`, `helm`, `curl`, `sq`, and `git` modules: commands now run in the background instead of freezing the UI. One that takes more than a moment opens a modal progress dialog with the command, a progress bar, its live output and a Cancel button; it closes on success and stays open on failure to show the error.
- `git` module moved from the `bdg/desktop` collection to `bdg/dev` (now `modules/bdg/dev/git`): its option is renamed `WISH_MODULE_BDG_DESKTOP_GIT` → `WISH_MODULE_BDG_DEV_GIT` and it is now off by default (enable with `-DWISH_MODULE_BDG_DEV_GIT=ON` or `-DWISH_COLLECTION_BDG_DEV=ON`); `--list` shows it as `bdg/dev/git`.
- `docker` Logs/Inspect and `kubectl` Logs/Describe windows now show their output in a read-only, syntax-highlighted `TextEditor` (logs: `log`, auto-scrolled to the newest line; Inspect: JSON; Describe: YAML) instead of a plain line table.
- `docker`, `kubectl`, and `git` modules: the windows open pre-arranged into a docked layout on the first run instead of as floating windows — `docker`/`kubectl` show a tabbed list column over a Console strip on the left with Logs + Inspect/Describe tabbed on the right; `git` fills the left with the commit graph over a Log strip and stacks Files over Diff on the right. - `docker` / `kubectl` modules: list, log, and console tables now scroll both horizontally and vertically; the Inspect / Describe views no longer clip long lines.
- `editor` module: loads `.yaml` / `.yml` UI files in addition to JSON, selected by file extension, with full feature parity — YAML syntax highlighting, schema-aware autocomplete, and the cursor-tracked Help panel / preview highlight all work for YAML sources.
- `editor` module: closing with unsaved edits now uses a real modal `MessageBox` ("Save changes … before closing?", Yes / No / Cancel) instead of an inline panel.
- `TextEditor`: new `"yaml"` value for the `language` field (YAML syntax highlighting); `wish_ui_schema` autocomplete now also applies when `language` is `"yaml"`.
- `CollapsingHeader`'s `open` field is now server-authoritative: it is forced into ImGui every frame (`ImGuiCond_Always`) instead of being applied once and then owned by ImGui. Update the field in the `toggled` handler to keep the header responsive to clicks. This fixes a spurious open/close oscillation when a `CollapsingHeader`'s subtree is rebuilt every frame.
- `--verbose` is now a verbosity level (`none` | `fatal` | `error` | `warning` | `info` | `trace`, default `none`) instead of an on/off flag. RMI trace lines and session lifecycle lines in `wish_logs/server.log` (and mirrored to stdout) are produced only at `info` and above; decoded call payloads (`args=`, `set` values, response bodies) only at `trace`. `fatal`/`error`/`warning` only raise the severity floor for client log messages. At `none` (the default) the server log stays silent and the trace string is never built.

- Server render loop: reduced per-frame CPU and heap-allocation churn — zero-copy string field access on the render/measure/arrange hot path, `ui_element::for_each_child_ordered()` no longer allocates per call, cached MenuBar-child detection, and fewer per-frame map/style copies in the render loop. No behavior change.
- Read-only RMI requests (`get` / `describe` / `dictionary` / `help`) no longer schedule redraw frames — a client polling widget values with `get` no longer holds a session at full framerate. Mutating requests (`set`, `call`, `instantiate`, …) are unaffected.
